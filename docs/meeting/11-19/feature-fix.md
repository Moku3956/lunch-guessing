# 確定したページと機能（MVP）

決まっていることだけを書いています。

## プロダクト

- アキネーター風の「お昼ごはん・夜ごはん決め」アプリ。キャラクターが「5段階（はい／たぶんそう／どちらでも／たぶん違う／いいえ」で答える質問をして、一番合う料理を3つ提案する。
- スマホ優先のレスポンシブなWebアプリ。PCでポートフォリオとして見る人も想定する。
- 画面の文言は日本語、ドキュメントは英語。
- **当てるキャラクター**が各画面でひとことしゃべる（キャラクターの設定はQ3）。

## ページ

| ページ | 確定した機能 |
| --- | --- |
| **スタート** | タイトル「今日のごはん、何にする？」、ゲーム開始ボタン、。 |
| **質問** | 質問を1問ずつ表示。回答ボタンは「はい／どちらでも／いいえ」。数字なしの **プログレスバー** を表示し、質問数の上限に向かって進む。途中で終わったときは一気に満タンになる。2問目からは「戻る」で前の回答を変えられる。回答ごとに読み込み中とエラーの表示がある。 |
| **考え中** | 最後の回答から結果までの短い演出。キャラクターのひとことを表示する。 |
| **結果** | 上位3品を🥇🥈🥉と一致度％で表示。料理ごとに「近くのお店を探す」（Googleマップ検索URL）と「レシピを見る」（レシピサイトの検索URL）。「もう一回」ボタン。ゲストには結果を保存するためのログインを案内する。「どれも違う」を置くかは未決。 |
| **マイページ** | 過去の結果の一覧。中身はQ1とQ2の回答で決まる。 |
| **エラー表示** | 別ページにはせず、今いるページの中に表示する。 |

## MVPに含めないもの

-ログイン
 +α機能のすべて（お気に入り、食事履歴によるスコア調整、PFCグラフ、適当回答の検知、冷蔵庫モード、AIによる質問生成）。
- 料理・属性・質問データの詳しい設計。仕様書では質問数と終わり方をパラメータとして扱う。
- 見た目のデザイン（Figmaなど）。
