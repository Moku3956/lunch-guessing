# 0001: 実行環境に Cloudflare Workers、DB に D1 を使う

- ステータス: 承認済み
- 日付: 2026-11-05

## 背景

- 常駐プロセスは不要で、リクエストごとに処理できるアプリです。
- DB には SQLite 系を使い、回答データを蓄積して継続的に学習させます。
- URL で公開でき、できるだけ無料枠で運用したいと考えています。
- 開発環境で Docker を使わない方針です（[0002](0002-use-mise-for-dev-environment.md)）。

## 決定

アプリの実行環境に Cloudflare Workers、DB に Cloudflare D1 を使います。

検討した他の案は次のとおりです。

- **Vercel + Turso:** 候補でしたが、Workers + D1 ならアプリと DB を 1 つのサービスにまとめられます。
- **Postgres + Neon:** 機能は豊富ですが、このアプリの要件には過剰で、開発用 DB の接続情報の共有も必要です。
- **Fly.io、Railway などに SQLite ファイルを置く:** 常駐プロセスが前提で、バックアップも自分で用意する必要があります。

## 影響

- `wrangler dev` により、Docker なしでローカルに Workers と D1 の環境を用意できます。
- フレームワークやライブラリは Workers で動くものを選ぶ必要があります。
- 対話的なトランザクションは使えないので、`batch()` でまとめて実行します。
- 無料枠は、ストレージ合計 5 GB、1 日あたり読み取り 500 万行、書き込み 10 万行です。D1 の読み取りはスキャンした行数で数えられるため、全件スキャンを避けます。
- 学習データの集計は Cron Triggers で実行できます。重いモデルの学習は Workers では行わず、必要になったら外部で実行します。
