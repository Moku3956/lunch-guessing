# 0002: 開発環境の統一に mise を使う

- ステータス: 承認済み
- 日付: 2026-11-05

## 背景

メンバーの開発環境をある程度揃え、その設定をリポジトリに含めたいと考えています。Docker は初期セットアップで躓きやすいため、候補から除外しました。

## 決定

ツールのバージョン、環境変数、共通タスクの管理に mise を使います。設定は `mise.toml` に書いてリポジトリで共有します。

Nix は OS レベルの依存まで固定できますが、学習コストが高く、このプロジェクトでは OS レベルの依存を固定する必要がないため採用しません。

## 影響

- DB は D1 を使い、ローカルでも `wrangler dev` で動くため、DB サーバーを別に起動する必要はありません（[0001](0001-use-cloudflare-workers-and-d1.md)）。
- 初回セットアップでは、`mise activate` のシェル設定と、必要に応じて `mise trust` の実行が必要です。
- Windows では、挙動の差を避けるため WSL2 の利用を推奨します。
- 依存パッケージのバージョンは、パッケージマネージャーのロックファイルで固定します。
- `mise.toml` は、フレームワークが決まって Node などのバージョンを指定できるようになった時点で追加します。
