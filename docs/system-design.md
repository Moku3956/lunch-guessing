# システム設計

要件は [requirements.md](requirements.md)、画面は [ui-design.md](ui-design.md) を参照してください。

最初に一番大事なのは**データ設計**です。料理×属性の表ができれば、ロジックはかなりシンプルに作れます。よければ料理50品の属性表を先に作ることもできます。

## データ設計

- [ ]  料理リストを作る。まず30〜50品くらい
- [ ]  料理ごとの属性を決める
    - 主食の種類：米、麺、パン、なし
    - 温度：熱々か冷たいか
    - 味の濃さ、こってりかさっぱりか
    - ジャンル：和、洋、中、エスニック
    - ガッツリ度、胃へのやさしさ
    - PFCとカロリー：+α用なので、ざっくりでOK
- [ ]  質問プールを作り、各質問がどの属性に対応するかを決める
- [ ]  回答の数値化を決める。はい=+1、どちらでも=0、いいえ=-1 など

## コアロジック

- [ ]  スコアリング：回答ごとに各料理の一致度を更新する
- [ ]  次の質問の選び方：最初はランダムでいい。慣れたら、残った候補を一番きれいに半分に分けられる質問を選ぶ方式にする。これが本家アキネーターに近い仕組み
- [ ]  終了条件：5〜7問で終える、または1位の一致度がしきい値を超えたら終える
- [ ]  上位3品と一致度%を出す
- [ ]  全部どちらでもと答えたときなど、候補が絞れない場合の処理
